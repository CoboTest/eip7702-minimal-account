### 与 E2E4337 的关键区别

| | E2E4337（无 Paymaster） | E2EPaymaster |
|-|------------------------|--------------|
| **Gas 资金来源** | Sponsor 向 EP 为 Alice 存款 | Paymaster 自身的 EP 存款支付 |
| **Alice 的 EP 余额** | 有 0.01 ETH 存款 | 0（Paymaster 承担） |
| **missingAccountFunds** | > 0（Alice 从 EP 存款中支付） | 0（Paymaster 支付） |
| **额外签名** | 无 | PM Signer 签署 EIP-712 授权 |
| **PM 签名方案** | 不适用 | **EIP-712 typed data**（绑定 chain + 合约地址） |
| **验证流程** | 仅 validateUserOp | validateUserOp + validatePaymasterUserOp |

## 关键技术说明

1. **OZ SignerEIP7702** 使用原始 ECDSA：`ecrecover(hash, sig) == address(this)`。UserOp 签名不带 EIP-191 前缀。
2. **VerifyingPaymaster** 使用 **EIP-712 typed data** + domain separator（绑定 chainId + paymaster 地址）实现防重放授权。包含 Ownable2Step、Pausable、ReentrancyGuard 和 signer/owner 分离。
3. **ERC-7821 mode** `0x01000000...` = 批量调用类型，使用 ERC-7579 执行编码。
4. **执行编码**: `abi.encode(Execution[])`，其中 `Execution = (address target, uint256 value, bytes callData)`。
5. **vm.setNonce 变通方案**仍然需要 — forge 模拟不能模拟 EIP-7702 auth 的 nonce 递增。
6. **`--gas-estimate-multiplier 500`** 对 type 4 交易是必需的，但会导致 delegated 账户发出的 type 2 交易 gas 估算过高。
7. **Paymaster 清理分两步执行**: E2EPaymaster 步骤 7 调用 `unlockStake()` + `withdrawTo()`。独立脚本 `PaymasterCleanup.s.sol` 在 `unstakeDelay` 过后处理 `withdrawStake()`。这是 forge 的限制：simulation 在单个 EVM pass 中运行所有 tx，因此同脚本中 `unlockStake()` + `withdrawStake()` 会报 "Stake withdrawal is not due"。
