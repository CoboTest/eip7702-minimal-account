### Signature Detail: EIP-7702 Delegation

**Signer:** Alice (EOA private key)
**Signed object:** Authorization tuple

**Fields:**

| Field | Value | Description |
|-------|-------|-------------|
| chainId | 11155111 | Sepolia chain ID (0 = any chain) |
| address | MinimalAccount address | Delegate implementation contract |
| nonce | 0 | Alice's current nonce (prevents replay) |

**Signing process:**
1. Compute `commit = keccak256(MAGIC || rlp(chainId, address, nonce))` where MAGIC = `0x05`
2. Alice signs `commit` with raw ECDSA → (v, r, s) / (yParity, r, s)
3. Authorization tuple = `(chainId, address, nonce, yParity, r, s)`

**Verification:** EVM validates during type 4 tx processing. If valid, sets `Alice.code = 0xef0100 || address` (23-byte delegation designator).

**Security:** Once delegation is set, Alice's EOA executes via MinimalAccount logic. Can be revoked by delegating to `address(0)` or re-delegating to another contract.

### Signature Detail: UserOp (v0.7)

**Signer:** Alice (EOA private key)
**Scheme:** Raw ECDSA (NOT EIP-191 personal_sign)

**Hash computation (v0.7 packed format):**

Step 1 — Pack UserOp fields:
```solidity
packHash = keccak256(abi.encode(
    sender,           // Alice's address
    nonce,            // EP nonce (0 for first op)
    keccak256(initCode),
    keccak256(callData),   // execute(BATCH_MODE, encoded batch)
    accountGasLimits,      // bytes32: verificationGasLimit(128bit) || callGasLimit(128bit)
    preVerificationGas,
    gasFees,               // bytes32: maxPriorityFeePerGas(128bit) || maxFeePerGas(128bit)
    keccak256(paymasterAndData)
))
```

Step 2 — Final hash with chain binding:
```solidity
userOpHash = keccak256(abi.encode(packHash, EntryPoint_address, chainId))
```

Step 3 — Sign:
```solidity
(v, r, s) = ecrecover(userOpHash, Alice_private_key)
signature = abi.encodePacked(r, s, v)   // 65 bytes
```

**Verifier:** `SignerEIP7702._rawSignatureValidation()` inside `validateUserOp()` — calls `ecrecover(hash, sig)` and checks recovered address == `address(this)` (Alice's EOA address, since delegation makes MinimalAccount code execute at Alice's address).

**Key difference from standard wallets:** No `"\x19Ethereum Signed Message:\n32"` prefix. Raw hash is signed directly. Standard ERC-4337 SDKs using `personal_sign` will produce INVALID signatures.

### Signature Detail: handleOps Bundle (Type 4 / EIP-7702)

**Signer:** Bundler
**Tx type:** EIP-7702 (type 4)

**Transaction content:**
- `to`: EntryPoint contract
- `data`: `handleOps(PackedUserOperation[], beneficiary)` — beneficiary = bundler address
- `authorizationList`: Contains Alice's signed EIP-7702 delegation

**What makes this special:**
The type 4 tx carries two things atomically in a single transaction:
1. **EIP-7702 authorization** — sets Alice's delegation code
2. **handleOps call** — executes the UserOp through EntryPoint

The EVM processes the authorization list FIRST (setting `Alice.code`), then executes the call. This is why delegation + UserOp execution can happen in a single tx.

### Signature Detail: Paymaster Authorization (EIP-712)

**Signer:** Deployer (acts as paymaster verifying signer)
**Scheme:** EIP-712 typed data

**EIP-712 Domain:**

| Field | Value |
|-------|-------|
| name | "VerifyingPaymaster" |
| version | "1" |
| chainId | 11155111 (Sepolia) |
| verifyingContract | Paymaster contract address |

**Typed Data:**
```solidity
PaymasterData(
    address sender,     // Alice's address
    uint256 nonce,      // EP nonce (0)
    uint48 validUntil,  // Expiry timestamp (block.timestamp + 1 hour)
    uint48 validAfter   // Start timestamp (0 = immediately)
)
```

**Hash computation:**
```solidity
domainSeparator = keccak256(abi.encode(
    DOMAIN_TYPEHASH,
    keccak256("VerifyingPaymaster"),
    keccak256("1"),
    chainId,
    paymaster_address
))

structHash = keccak256(abi.encode(
    PAYMASTER_DATA_TYPEHASH,
    sender, nonce, validUntil, validAfter
))

pmHash = keccak256(0x19 || 0x01 || domainSeparator || structHash)
```

**Signing:**
```solidity
(v, r, s) = ecrecover(pmHash, deployer_private_key)
```

**paymasterAndData layout (packed):**
```
bytes: [paymaster_address (20)] [pmVerificationGas (16)] [pmPostOpGas (16)] [validUntil (6)] [validAfter (6)] [r (32)] [s (32)] [v (1)]
Total: 129 bytes
```

**Verifier:** `VerifyingPaymaster._validatePaymasterUserOp()` — extracts fields from `paymasterAndData`, recomputes `pmHash`, calls `ECDSA.recover(pmHash, sig)`, checks recovered address == `verifyingSigner`.

**Security:**
- Domain separator binds to chainId + paymaster address → cross-chain replay protection
- validUntil/validAfter → time-bounded authorization window
- Signer can be rotated without redeploying paymaster (signer/owner separation)

### Signature Detail: EIP-7702 Delegation

**Signer:** Alice (EOA private key)
**Signed object:** Authorization tuple

**Fields:**

| Field | Value | Description |
|-------|-------|-------------|
| chainId | 11155111 | Sepolia chain ID (0 = any chain) |
| address | MinimalAccount address | Delegate implementation contract |
| nonce | 0 | Alice's current nonce (prevents replay) |

**Signing process:**
1. Compute `commit = keccak256(MAGIC || rlp(chainId, address, nonce))` where MAGIC = `0x05`
2. Alice signs `commit` with raw ECDSA → (v, r, s) / (yParity, r, s)
3. Authorization tuple = `(chainId, address, nonce, yParity, r, s)`

**Verification:** EVM validates during type 4 tx processing. If valid, sets `Alice.code = 0xef0100 || address` (23-byte delegation designator).

**Security:** Once delegation is set, Alice's EOA executes via MinimalAccount logic. Can be revoked by delegating to `address(0)` or re-delegating to another contract.

### Signature Detail: UserOp (Pimlico, v0.7)

Same as Self-Bundled UserOp signature above. The hash computation is identical — v0.7 packed format.

The only difference is operational: Self-Bundled computes `userOpHash` via Forge's `_getUserOpHash()` helper; Pimlico computes it in Python using `hash.compute_userop_hash()` — a pure function implementing the same packed keccak format.

## 6. Key Technical Notes

1. **Raw ECDSA:** OZ `SignerEIP7702` uses `ecrecover(hash, sig)`, NOT `personal_sign`. Standard ERC-4337 SDKs using `personal_sign` won't work.
2. **EIP-7702 delegation:** Signed off-chain by Alice, included in type 4 tx `authorizationList` by bundler.
3. **Forge gas estimation:** `--gas-estimate-multiplier 500` needed for type 4 txs.
4. **UserOp hash (v0.7):** `keccak256(abi.encode(packHash, EP, chainId))` — locally computable.
5. **Paymaster EIP-712:** Domain binds to `chainId` + paymaster address for cross-chain replay protection.
6. **Two-phase paymaster cleanup:** `unlockStake` in main script, `withdrawStake` in separate script (Forge simulates in single EVM pass).
7. **`eip7702Auth`:** Pimlico API parameter that atomically bundles delegation with UserOp.
8. **All USDC amounts** unified to 1 USDC (0.6 + 0.4 batch), round-trip Sponsor → Alice → Sponsor.
