```bash
  --rpc-url $RPC_URL --broadcast --slow --gas-estimate-multiplier 500

  --rpc-url $RPC_URL --broadcast --slow --gas-estimate-multiplier 500
```

> **Why two phases?** EIP-7702 delegation authorization increments Alice's nonce. Forge caches nonces at simulation time and doesn't account for this on-chain side effect, causing "nonce too low" errors when Alice sends subsequent txs in the same script run.

## Comparison: ERC-4337 vs Direct

| | ERC-4337 | Direct |
|-|----------|--------|
| **Actors** | 4 (Deployer, Sponsor, Bundler, Alice) | 2 (Deployer, Alice) |
| **On-chain txs** | 4 | 5 (3 setup + 2 Alice) |
| **Alice pays gas** | ❌ (Sponsor/Bundler) | ✅ (pays own gas) |
| **Alice signs** | UserOp + delegation (off-chain) | Delegation (off-chain) + sends 2 txs |
| **Delegation carrier** | Bundler's type 4 tx | Deployer's type 4 tx |
| **Delegation persistent** | ✅ | ✅ |
| **Alice calls separately** | N/A (all via UserOp) | execute() + executeBatch() |
| **Requires EntryPoint** | ✅ | ❌ |

### Key difference: delegation carrier

Both flows have a **third party** (Bundler or Deployer) carry Alice's delegation in their type 4 tx. This is required because:

1. EIP-7702 authorization **increments Alice's nonce** during processing
2. If Alice sends the type 4 tx herself, the auth nonce (0) and tx nonce (0) conflict
3. Etherscan shows `Validity: False` for self-carried delegations (auth nonce mismatch)

## Key Insights

1. **EIP-7702 delegation signing**: Alice signs `(chainId, implementationAddress, nonce)` off-chain via `vm.signDelegation()`. The `(v, r, s)` is embedded in a type 4 tx authorization list. EVM processes authorizations before execution.

2. **Delegation must be carried by a third party**: When Alice sends her own type 4 tx, the auth nonce and tx nonce both start at 0, causing an auth nonce conflict. A third party (Bundler/Deployer) avoids this because their tx nonce is independent of Alice's auth nonce.

3. **forge + EIP-7702 nonce issue**: Forge doesn't account for EIP-7702 auth nonce increments during simulation. Solution: split into two phases so forge queries the correct nonce for Alice's txs.

4. **Gas estimation**: `--gas-estimate-multiplier 500` needed for type 4 txs (forge underestimates EIP-7702 authorization processing gas).

5. **Deterministic Alice**: `keccak256("alice-...", block.number, block.timestamp)` ensures fresh keypair each run.
