| execute() single | Alice | EIP-1559 (type 2) | transaction | EVM | Step 4 | 🔴 Per-operation |
| execute() batch | Alice | EIP-1559 (type 2) | transaction | EVM | Step 5 | 🔴 Per-operation |

> **Frequency legend:** 🔵 One-time = deploy/setup. 🟡 Per-user = once per new user onboarding. 🔴 Per-operation = every time Alice executes. ⚪ Demo-only = test setup, not needed in production.

### Key Difference: No UserOp Signature Needed

Direct execution path does not go through EntryPoint:
- No `userOp.signature` needed (no UserOp)
- No Paymaster
- Alice's EVM transaction signature is the authorization itself
- ERC-7821 `_erc7821AuthorizedExecutor` checks `msg.sender == address(this)` (Alice calls herself)

## Key Technical Notes

1. **ERC-4337 v0.8 userOpHash is EIP-712** — Unlike v0.7 where `userOpHash = keccak256(packUserOp || EP || chainId)`, v0.8 uses EIP-712 typed data with the EntryPoint's domain separator. Scripts must call `EP.getUserOpHash(op)` via staticcall (cannot replicate locally). OZ's `_signableUserOpHash()` handles this automatically.
2. **OZ SignerEIP7702** uses raw ECDSA: `ecrecover(hash, sig) == address(this)`. UserOp signatures have no EIP-191 prefix.
3. **VerifyingPaymaster** uses **EIP-712 typed data** with domain separator (binds to chainId + paymaster address) for replay-proof authorization. Includes Ownable2Step, Pausable, ReentrancyGuard, and signer/owner separation.
4. **ERC-7821 mode** `0x01000000...` = batch call type, using ERC-7579 execution encoding.
5. **Execution encoding**: `abi.encode(Execution[])` where `Execution = (address target, uint256 value, bytes callData)`.
6. **vm.setNonce workaround** still needed — forge simulation does not model EIP-7702 auth nonce increment.
7. **`--gas-estimate-multiplier 500`** required for type 4 transactions but causes over-estimation for type 2 txs from delegated accounts.
8. **Paymaster cleanup is two-phase**: Step 7 in E2EPaymaster calls `unlockStake()` + `withdrawTo()`. A separate `PaymasterCleanup.s.sol` script handles `withdrawStake()` after `unstakeDelay` has elapsed. This is due to a forge limitation: simulation runs all txs in a single EVM pass, so `unlockStake()` + `withdrawStake()` in the same script fails with "Stake withdrawal is not due".
