# EntryPoint v0.7 vs v0.8 — 差异对比

本文档对比本项目在 ERC-4337 EntryPoint v0.7（`main` 分支）和 v0.8（`feature/entrypoint-v08` 分支）上的实现差异。

## 概览

| | v0.7 (`main`) | v0.8 (`feature/entrypoint-v08`) |
|---|---|---|
| EntryPoint 地址 | `0x0000000071727De22E5E9d8BAf0edAc6f37da032` | `0x4337084D9E255Ff0702461CF8895CE9E3b5Ff108` |
| userOpHash 计算 | `keccak256(packUserOp \|\| EP \|\| chainId)` | EIP-712 typed data（EP 内部 domain separator） |
| EIP-7702 原生支持 | ❌ 无 | ✅ `initCode` marker + delegation 校验 |
| OZ 常量 | `ERC4337Utils.ENTRYPOINT_V07` | `ERC4337Utils.ENTRYPOINT_V08` |

## 1. 合约代码差异

**只有一行代码不同**：`entryPoint()` 返回的常量。

```diff
- return ERC4337Utils.ENTRYPOINT_V07;
+ return ERC4337Utils.ENTRYPOINT_V08;
```

MinimalAccount 本体（`Account` + `SignerEIP7702` + `ERC7821`）、VerifyingPaymaster 的所有逻辑在两个版本中 **完全相同**。

## 2. userOpHash 计算方式

这是最核心的架构差异。

### v0.7 — 本地计算

```solidity
// 可以纯 off-chain 计算，不需要调用链上合约
bytes32 packed = keccak256(abi.encode(
    op.sender, op.nonce,
    keccak256(op.initCode), keccak256(op.callData),
    op.accountGasLimits, op.preVerificationGas,
    op.gasFees, keccak256(op.paymasterAndData)
));
bytes32 userOpHash = keccak256(abi.encode(packed, address(EP), block.chainid));
```

**特点**：
- 确定性公式，可在任意环境复现
- `initCode` 以原始字节参与 hash
- 不包含 delegation 信息

### v0.8 — EIP-712 + EP staticcall

```solidity
// 必须调用 EP 合约（依赖 EP 的 EIP-712 domain separator）
(bool ok, bytes memory ret) = address(EP).staticcall(
    abi.encodeWithSignature("getUserOpHash(...)", op)
);
bytes32 userOpHash = abi.decode(ret, (bytes32));
```

**特点**：
- EIP-712 domain：`name="ERC4337"`, `version="1"`, `chainId`, `verifyingContract=EP`
- 不可本地复现（依赖 EP 内部 `_domainSeparatorV4()`）
- 当 `initCode` 以 `0x7702` 开头时，hash 中包含 delegation address

## 3. 原生 EIP-7702 支持（v0.8 独有）

v0.8 EntryPoint 新增 `Eip7702Support` 库，提供三项原生功能：

### 3a. initCode `0x7702` Marker

UserOp 的 `initCode` 设为 20 字节的 `0x7702000...000`（左对齐），告诉 EP："这是 EIP-7702 账户，不要按 factory 部署处理"。

```solidity
// v0.7: initCode 为空
initCode: ""

// v0.8: 使用 EIP-7702 marker
initCode: abi.encodePacked(bytes20(bytes2(0x7702)))
// = 0x7702000000000000000000000000000000000000
```

### 3b. delegation address 绑定到 userOpHash

EP 调用 `EXTCODECOPY` 读取 sender 的前 23 字节，验证 `0xef0100` 前缀（EIP-7702 delegation 标记），提取 delegation target address，然后将其包含在 hash 计算中：

```
initCodeHash = keccak256(delegateAddress)  // 替代原始 keccak256(initCode)
```

**安全意义**：Alice 签署的 UserOp 只对特定的 delegation target 有效。如果 delegation 被替换为恶意合约，签名失效。

### 3c. EP 自动校验 delegation

`_createSenderIfNeeded()` 识别 `0x7702` marker 后，跳过 factory 部署逻辑，改为校验 sender 确实设置了 EIP-7702 delegation。

### 3d. Bundler API `eip7702Auth`（本项目未使用）

v0.8 规范在 `eth_sendUserOperation` RPC 中新增 `eip7702Auth` 参数，让 bundler 在 bundle tx 的 `authorizationList` 中附带 delegation auth。本项目使用 Forge Script 直接 broadcast type 4 tx，绕过 bundler RPC。

## 4. E2E Script 流程差异

### v0.7 流程

```
Step 5: Alice 签 UserOp（initCode 为空）
Step 6: Alice 签 delegation（off-chain）→ Bundler broadcast handleOps（type 4 tx，authorizationList 携带 delegation）
```

UserOp 签名和 delegation 签名是独立的，可以分步完成。

### v0.8 流程

```
Step 5: Alice 签 delegation（off-chain）→ 附加到 EVM → Alice 签 UserOp（initCode = 0x7702 marker）
Step 6: Bundler broadcast handleOps（type 4 tx，delegation 已附加）
```

**关键约束**：`EP.getUserOpHash()` 需要 `EXTCODECOPY` 读取 Alice 的 delegation code，所以 `vm.attachDelegation()` 必须在 `getUserOpHash()` 之前。

## 5. 签名差异

签名算法本身（raw ECDSA via `SignerEIP7702`）在两个版本中相同。区别在于被签名的 hash 内容：

| | v0.7 | v0.8 |
|---|---|---|
| hash 算法 | `keccak256(pack \|\| EP \|\| chainId)` | EIP-712 `TypedDataHash(domain, structHash)` |
| 包含 delegation | ❌ | ✅（通过 initCode override） |
| 可本地计算 | ✅ | ❌（需 staticcall EP） |
| 跨链重放保护 | ✅（chainId 直接参与） | ✅（EIP-712 domain 包含 chainId） |

## 6. VerifyingPaymaster

**两个版本完全相同**。Paymaster 的 EIP-712 签名是独立于 EP userOpHash 的，使用自己的 domain separator（绑定到 paymaster 合约地址 + chainId）。

## 7. 迁移指南

从 v0.7 迁移到 v0.8 只需：

1. **合约**：`ENTRYPOINT_V07` → `ENTRYPOINT_V08`（一行代码）
2. **Script**：
   - EP 地址常量更新
   - `_getUserOpHash()` 改为 staticcall EP
   - `initCode` 设为 `0x7702` marker
   - delegation 提前到 hash 计算之前
3. **重新部署**：MinimalAccount 和 VerifyingPaymaster（因为 EP 地址硬编码在合约中）
