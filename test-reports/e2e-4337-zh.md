### 签名详解：EIP-7702 委托

**签名者：** Alice（EOA 私钥）
**签名对象：** Authorization 元组

**字段：**

| 字段 | 值 | 说明 |
|------|-----|------|
| chainId | 11155111 | Sepolia 链 ID（0 = 任意链） |
| address | MinimalAccount 地址 | 委托实现合约 |
| nonce | 0 | Alice 当前 nonce（防止重放） |

**签名过程：**
1. 计算 `commit = keccak256(MAGIC || rlp(chainId, address, nonce))`，其中 MAGIC = `0x05`
2. Alice 用原始 ECDSA 签名 `commit` → (v, r, s) / (yParity, r, s)
3. Authorization 元组 = `(chainId, address, nonce, yParity, r, s)`

**验证：** EVM 在处理 type 4 交易时验证。若有效，设置 `Alice.code = 0xef0100 || address`（23 字节委托指示符）。

**安全性：** 委托设置后，Alice 的 EOA 通过 MinimalAccount 逻辑执行。可通过委托给 `address(0)` 或重新委托给其他合约来撤销。

### 签名详解：UserOp (v0.7)

**签名者：** Alice（EOA 私钥）
**方案：** Raw ECDSA（非 EIP-191 personal_sign）

**哈希计算（v0.7 packed 格式）：**

第 1 步 — 打包 UserOp 字段：
```solidity
packHash = keccak256(abi.encode(
    sender,           // Alice 的地址
    nonce,            // EP nonce（首次操作为 0）
    keccak256(initCode),
    keccak256(callData),   // execute(BATCH_MODE, encoded batch)
    accountGasLimits,      // bytes32: verificationGasLimit(128bit) || callGasLimit(128bit)
    preVerificationGas,
    gasFees,               // bytes32: maxPriorityFeePerGas(128bit) || maxFeePerGas(128bit)
    keccak256(paymasterAndData)
))
```

第 2 步 — 带链绑定的最终哈希：
```solidity
userOpHash = keccak256(abi.encode(packHash, EntryPoint_address, chainId))
```

第 3 步 — 签名：
```solidity
(v, r, s) = ecrecover(userOpHash, Alice_private_key)
signature = abi.encodePacked(r, s, v)   // 65 字节
```

**验证方：** `SignerEIP7702._rawSignatureValidation()`（在 `validateUserOp()` 内部）— 调用 `ecrecover(hash, sig)` 并检查恢复的地址 == `address(this)`（Alice 的 EOA 地址，因为委托使 MinimalAccount 代码在 Alice 地址上执行）。

**与标准钱包的关键区别：** 无 `"\x19Ethereum Signed Message:\n32"` 前缀。直接签名原始哈希。使用 `personal_sign` 的标准 ERC-4337 SDK 将产生无效签名。

### 签名详解：handleOps 捆绑交易 (Type 4 / EIP-7702)

**签名者：** Bundler
**交易类型：** EIP-7702 (type 4)

**交易内容：**
- `to`：EntryPoint 合约
- `data`：`handleOps(PackedUserOperation[], beneficiary)` — beneficiary = bundler 地址
- `authorizationList`：包含 Alice 签名的 EIP-7702 委托

**特殊之处：**
type 4 交易在单笔交易中原子化地携带两样东西：
1. **EIP-7702 授权** — 设置 Alice 的委托代码
2. **handleOps 调用** — 通过 EntryPoint 执行 UserOp

EVM 先处理 authorization list（设置 `Alice.code`），然后执行调用。这就是为什么委托 + UserOp 执行可以在单笔交易中完成。

### 签名详解：Paymaster 授权 (EIP-712)

**签名者：** Deployer（充当 paymaster 验证签名者）
**方案：** EIP-712 typed data

**EIP-712 Domain：**

| 字段 | 值 |
|------|-----|
| name | "VerifyingPaymaster" |
| version | "1" |
| chainId | 11155111 (Sepolia) |
| verifyingContract | Paymaster 合约地址 |

**Typed Data：**
```solidity
PaymasterData(
    address sender,     // Alice 的地址
    uint256 nonce,      // EP nonce (0)
    uint48 validUntil,  // 过期时间戳 (block.timestamp + 1 小时)
    uint48 validAfter   // 生效时间戳 (0 = 立即生效)
)
```

**哈希计算：**
```solidity
domainSeparator = keccak256(abi.encode(
    DOMAIN_TYPEHASH,
    keccak256("VerifyingPaymaster"),
    keccak256("1"),
    chainId,
    paymaster_address
))

structHash = keccak256(abi.encode(
    PAYMASTER_DATA_TYPEHASH,
    sender, nonce, validUntil, validAfter
))

pmHash = keccak256(0x19 || 0x01 || domainSeparator || structHash)
```

**签名：**
```solidity
(v, r, s) = ecrecover(pmHash, deployer_private_key)
```

**paymasterAndData 布局（packed）：**
```
bytes: [paymaster_address (20)] [pmVerificationGas (16)] [pmPostOpGas (16)] [validUntil (6)] [validAfter (6)] [r (32)] [s (32)] [v (1)]
总计: 129 字节
```

**验证方：** `VerifyingPaymaster._validatePaymasterUserOp()` — 从 `paymasterAndData` 中提取字段，重新计算 `pmHash`，调用 `ECDSA.recover(pmHash, sig)`，检查恢复的地址 == `verifyingSigner`。

**安全性：**
- Domain separator 绑定 chainId + paymaster 地址 → 跨链重放保护
- validUntil/validAfter → 有时间限制的授权窗口
- 签名者可以在不重新部署 paymaster 的情况下轮换（签名者/所有者分离）


**验证方：** `SignerEIP7702._rawSignatureValidation()`（在 `validateUserOp()` 内部）— 调用 `ecrecover(hash, sig)` 并检查恢复的地址 == `address(this)`（Alice 的 EOA 地址，因为委托使 MinimalAccount 代码在 Alice 地址上执行）。

**与标准钱包的关键区别：** 无 `"\x19Ethereum Signed Message:\n32"` 前缀。直接签名原始哈希。使用 `personal_sign` 的标准 ERC-4337 SDK 将产生无效签名。

### 签名详解：handleOps 捆绑交易 (Type 4 / EIP-7702)

**签名者：** Bundler
**交易类型：** EIP-7702 (type 4)

**交易内容：**
- `to`：EntryPoint 合约
- `data`：`handleOps(PackedUserOperation[], beneficiary)` — beneficiary = bundler 地址
- `authorizationList`：包含 Alice 签名的 EIP-7702 委托

**特殊之处：**
type 4 交易在单笔交易中原子化地携带两样东西：
1. **EIP-7702 授权** — 设置 Alice 的委托代码
2. **handleOps 调用** — 通过 EntryPoint 执行 UserOp

EVM 先处理 authorization list（设置 `Alice.code`），然后执行调用。这就是为什么委托 + UserOp 执行可以在单笔交易中完成。

### 签名详解：EIP-7702 委托

**签名者：** Alice（EOA 私钥）
**签名对象：** Authorization 元组

**字段：**

| 字段 | 值 | 说明 |
|------|-----|------|
| chainId | 11155111 | Sepolia 链 ID（0 = 任意链） |
| address | MinimalAccount 地址 | 委托实现合约 |
| nonce | 0 | Alice 当前 nonce（防止重放） |

**签名过程：**
1. 计算 `commit = keccak256(MAGIC || rlp(chainId, address, nonce))`，其中 MAGIC = `0x05`
2. Alice 用原始 ECDSA 签名 `commit` → (v, r, s) / (yParity, r, s)
3. Authorization 元组 = `(chainId, address, nonce, yParity, r, s)`

**验证：** EVM 在处理 type 4 交易时验证。若有效，设置 `Alice.code = 0xef0100 || address`（23 字节委托指示符）。

**安全性：** 委托设置后，Alice 的 EOA 通过 MinimalAccount 逻辑执行。可通过委托给 `address(0)` 或重新委托给其他合约来撤销。

### 签名详解：UserOp (Pimlico, v0.7)

与 Self-Bundled 的 UserOp 签名相同。哈希计算完全一致 — v0.7 packed 格式。

唯一的区别在于操作方式：Self-Bundled 通过 Forge 的 `_getUserOpHash()` 辅助函数计算 `userOpHash`；Pimlico 在 Python 中通过 `hash.compute_userop_hash()` 计算 — 一个实现相同 packed keccak 格式的纯函数。

## 6. 关键技术说明

1. **Raw ECDSA：** OZ `SignerEIP7702` 使用 `ecrecover(hash, sig)`，而非 `personal_sign`。使用 `personal_sign` 的标准 ERC-4337 SDK 无法兼容。
2. **EIP-7702 委托：** 由 Alice 链下签名，由 bundler 在 type 4 tx 的 `authorizationList` 中携带。
3. **Forge gas 估算：** type 4 交易需要 `--gas-estimate-multiplier 500`。
4. **UserOp hash (v0.7)：** `keccak256(abi.encode(packHash, EP, chainId))` — 可本地计算。
5. **Paymaster EIP-712：** domain 绑定 `chainId` + paymaster 地址，防止跨链重放。
6. **两阶段 paymaster 清理：** `unlockStake` 在主脚本中执行，`withdrawStake` 在单独脚本中执行（Forge 在单个 EVM pass 中模拟）。
7. **`eip7702Auth`：** Pimlico API 参数，将委托与 UserOp 原子化捆绑。
8. **所有 USDC 金额**统一为 1 USDC (0.6 + 0.4 批量)，Sponsor → Alice → Sponsor 往返。
